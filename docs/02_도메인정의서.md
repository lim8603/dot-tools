## 1. 개요

이 문서는 DevSwitcher Tools 프로젝트에서 사용하는 도메인 용어, 약어, 도메인 규칙을 정의하여 팀의 공통 언어를 확립한다.

DevSwitcher Tools는 여러 프로그래밍 언어의 전환·빌드·실행·디버그를 하나의 VSCode 상태바 UX로 통합하는 확장이다. 언어별 차이는 `LanguageAdapter` 인터페이스와 `ChipDescriptor[]` 선언 뒤로 숨기는 것이 설계의 핵심이며, 본 문서의 용어들은 이 아키텍처를 중심으로 구성된다.

> **범위 주석 (v1.0.0 현재와의 차이)**: 기준 문서인 용어집은 초기 설계(설계서 v1.1) 반입 시점 기준으로 작성되어 **Rust(Cargo) 중심의 예시·서술**이 포함되어 있다. v1.2.0 현재는 7개 툴체인(Rust · C++/CMake · C++/Visual Studio · C# · Python · Go · Node.js/TypeScript)을 지원하므로, Cargo 전용으로 서술된 항목(예: `Features`, `compiler-artifact`, BR-004)은 **Rust 어댑터 기준의 대표 예시**로 읽어야 한다. 원문 정의는 왜곡 없이 유지하고, 해당 항목에 개별 주석을 달았다.

## 2. 핵심 용어 정의

> 가독성을 위해 기준 문서의 단일 용어표를 주제별로 재배치했다. 정의 내용은 기준 문서와 동일하다.

### 2.1 아키텍처 핵심 개념

| 용어(영문) | 용어(한글) | 정의 | 근거 |
| --- | --- | --- | --- |
| LanguageAdapter | 언어 어댑터 | 언어별 빌드/디버그/실행 로직을 캡슐화한 인터페이스. 이 설계의 핵심 — 언어 차이를 이 뒤로 숨긴다 | 상세 §4 |
| ChipDescriptor | 칩 디스크립터 | 어댑터가 상태바 칩 하나를 선언하는 구조(id·icon·label·listItems·format 등). 개념설계의 Capabilities를 대체 | DD-03 |
| Capabilities | 능력(구 구조) | 개념설계에서 어댑터가 지원 칩을 boolean으로 선언하던 구조. 상세설계에서 `ChipDescriptor[]`로 교체됨 — **폐기됨(→ ChipDescriptor)** | — |
| Adapter Registry | 어댑터 레지스트리 | 설치된 어댑터 관리·워크스페이스 스캔·어댑터 매칭 담당 | 상세 §3.1 |
| Orchestrator | 오케스트레이터 | 활성 컨텍스트 관리·명령 처리·어댑터 위임 담당 | 상세 §3.1 |
| ManifestWatcher | 매니페스트 감시자 | 매니페스트 변경 감지 후 디바운스 재스캔 | F17 |
| Doctor | 진단 | 활성 어댑터의 전제조건을 일괄 점검하고 등급별 해결 액션을 제공하는 진단 명령 | F19 |
| Project Init Wizard | 시작 마법사 | 매니페스트 없는 폴더에서 언어를 골라 네이티브 도구로 새 프로젝트를 생성하는 수동 명령. 파일 부재의 능동 복구 경로 | F20, ADR-010 |

### 2.2 상태·데이터 개념

| 용어(영문) | 용어(한글) | 정의 | 근거 |
| --- | --- | --- | --- |
| SSOT 파사드 | 단일 진실 파사드 | 값은 각 언어의 캐노니컬 파일에만 두고, 확장은 포인터·선택 상태만 소유하는 원칙 | DD-07 |
| Selection | 선택 상태 | 프로젝트별 칩 선택값(`values`)과 실행 인자(`runArgs`) | 상세 §4 |
| workspaceState | 워크스페이스 상태 | VSCode Memento API — 워크스페이스별·기계 로컬 키-값 저장소. 선택 상태 저장 위치 | DD-01 |
| reconcile | 재검증 | 저장된 선택 상태를 현재 스캔 결과와 대조해 무효 항목을 정리하는 절차 | 상세 §6.2 |

### 2.3 실행 개념

| 용어(영문) | 용어(한글) | 정의 | 근거 |
| --- | --- | --- | --- |
| Task API | 태스크 API | `vscode.tasks.*` — 종료 코드 감지와 problem matcher를 제공하는 작업 실행 API | DD-02 |
| ProcessExecution | 프로세스 실행 | Task 실행 방식. 인자 배열을 그대로 전달해 셸 이스케이프 문제를 원천 차단 | 상세 §7.1 |
| compiler-artifact | 컴파일 산출물 메시지 | `cargo build --message-format=json` 출력에서 실행 파일 경로를 알리는 메시지 | DD-05 |

> **주석**: `compiler-artifact`는 Rust(Cargo) 어댑터에 해당하는 용어다. v1.0.0의 나머지 5개 언어에서 산출물 경로를 확보하는 방식은 기준 문서에 등재되어 있지 않다(§5 참조).

### 2.4 칩(선택 축) 용어

| 용어(영문) | 용어(한글) | 정의 | 근거 |
| --- | --- | --- | --- |
| ChipItem | 칩 항목 | QuickPick에 나열되는 선택지 하나(id·label·description·detail) | — |
| Target | 타깃 | 실행/빌드 대상(bin/example, 시작 프로젝트, 진입 스크립트). required 칩 | F9 |
| Profile | 프로파일 | 빌드 변형(dev/release/커스텀). 컴파일 언어만 해당 | F7 |
| Architecture | 아키텍처 | target triple/RID 등 대상 아키텍처. 컴파일 언어만 해당 | F10 |
| Features | 피처 | Cargo features 조합(`--features`/`--no-default-features`). multiSelect 칩 | F15 |
| Environment | 환경 | venv/conda 등 인터프리터 환경. 스크립트 언어만 해당 | F11 |

> **주석**: `Features`의 정의는 Rust(Cargo) 기준으로 서술되어 있다. 또한 기준 문서는 `Environment`를 "v1 정의만"으로 표기했는데, 이는 초기 범위(Rust 실구현, 나머지 언어 스텁) 기준 서술이다. v1.0.0에서의 `Environment` 칩 구현 상태는 기준 문서에서 확인되지 않아 **미확정**이다(§5 참조).

### 2.5 VSCode 플랫폼·배포 용어

| 용어(영문) | 용어(한글) | 정의 | 근거 |
| --- | --- | --- | --- |
| QuickPick | 퀵픽 | 명령 팔레트식 드롭다운(= 칩의 "콤보박스") | — |
| StatusBarItem | 상태바 항목 | 하단 상태바의 클릭 가능한 칩/버튼 | — |
| Extension Development Host | 확장 개발 호스트 | F5로 뜨는, 개발 중 확장이 로드된 별도 VSCode 창 | — |
| VSIX | 확장 패키지 | VSCode 확장 배포 패키지 파일 | — |
| extensionKind | 확장 종류 | 확장이 UI 측/워크스페이스(원격) 측 어디서 실행될지 선언하는 매니페스트 필드 | DD-08 |
| on-demand install | 온디맨드 설치 | 필요 확장을 최초 사용 시점에 확인·자동 설치하는 방식. `extensionDependencies` 하드 의존을 대체 | DD-09 |

## 4. 도메인 규칙 (Business Rules)

| ID | 규칙 | 근거 |
| --- | --- | --- |
| BR-001 | 값은 각 언어의 캐노니컬 파일에만 존재하고 확장은 복제하지 않는다 | DD-07 (SSOT) |
| BR-002 | 선택 상태는 workspaceState에 프로젝트별로 독립 저장한다 | DD-01 |
| BR-003 | 상태바·오케스트레이터·설정 UI는 `LanguageAdapter`/`ChipDescriptor[]`만 알고 특정 언어를 모른다 | DD-03 |
| BR-004 | 산출물 경로는 조합하지 않고 cargo가 알려주는 값을 쓴다 | DD-05 |
| BR-005 | 한 VSCode 창은 하나의 실행 환경에만 연결된다 (한 창 = 한 환경) | 상세 §12.4 |
| BR-006 | 의존성은 하드 강제하지 않고 최초 사용 시점에 온디맨드 처리한다 | DD-09 |

> **주석**: BR-004는 Rust(Cargo) 기준으로 서술된 규칙이다. 규칙의 취지(산출물 경로를 확장이 조합하지 않고 빌드 도구가 알려주는 값을 신뢰한다)는 언어 불문 원칙이나, 타 언어에서의 구체 적용 방식은 기준 문서에 등재되어 있지 않다.

## 5. v1.0.0 미등재 용어 (미확정)

v1.0.0 릴리즈에는 아래 개념들이 포함되어 있으나, 기준 문서(용어집 v1)에 정의가 등재되어 있지 않다. 공식 산출물 생성 규칙에 따라 근거 없는 정의를 추가하지 않고 **미확정**으로 명시한다. 용어집 갱신(다음 개정) 시 정식 정의 등재가 필요하다.

| 용어 | 상태 | 비고 |
| --- | --- | --- |
| Run Group (실행 그룹) | **미확정** — 용어집 미등재 | 여러 프로젝트를 종속 순서대로 일괄 기동/정리하는 v1.0.0 기능. 정식 정의는 ADR-015 참조 필요 |
| 준비 감지 (readiness) | **미확정** — 용어집 미등재 | Run Group 멤버의 준비 신호(포트/헬스체크) 판정 기능(v0.8.0/MS-018). 정식 정의 등재 필요 |
| InvocationConfig 오버레이 | **미확정** — 용어집 미등재 | 파일 무편집 호출 구성 개념. 계약은 `interface_contract.md` §7에 존재하나 용어집에는 미반영 |
| Environment 칩의 v1.0.0 구현 상태 | **미확정** | 용어집은 초기 범위 기준 "v1 정의만"으로 표기. 현재 구현 여부는 기준 문서에서 확인 불가 |
| 타 언어(C++/C#/Python/Go/Node.js) 어댑터별 산출물 경로 확보 방식 | **미확정** | 용어집에는 Rust(`compiler-artifact`)만 등재 |

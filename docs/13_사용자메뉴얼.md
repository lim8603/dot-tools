## 1. 소개

DevSwitcher Tools는 VS Code 상태바를 **프로젝트 조종석(cockpit)** 으로 바꾸는 확장이다. 활성 프로젝트, 빌드 프로파일, 타깃 등 빌드 옵션을 상태바 **칩(chip)** 으로 선택하고, **Build / Run / Debug** 버튼 한 번으로 각 언어의 네이티브 툴체인(CLI)을 구동한다.

핵심 원칙:

- **언어가 달라도 UX는 하나.** Cargo·.NET·Python·CMake·Go·Node 어느 프로젝트든 같은 상태바 워크플로를 쓴다.
- **캐노니컬 파일 무편집.** `Cargo.toml`, `.csproj`, `CMakeLists.txt`, `pyproject.toml`, `go.mod`, `package.json`은 절대 수정하지 않는다. 옵션은 호출 시점에 `--config`, `-p:`, `-D`, `RUSTFLAGS`, 환경변수 등으로 주입된다.
- **디버거 자동 선택.** 툴체인에 맞는 디버거를 자동으로 고르고, 필요한 확장은 최초 디버그 시 온디맨드로 설치를 안내한다.

### 1.1 지원 언어

| 언어 | 감지 파일 | Build | Run | Debug | 툴체인 · 디버그 확장 |
| --- | --- | :---: | :---: | :---: | --- |
| Rust (Cargo) | `Cargo.toml` | ✅ | ✅ | ✅ | `rustup` + `cargo` · CodeLLDB |
| C# (.NET) | `*.csproj` | ✅ | ✅ | ✅ | .NET SDK · C# Dev Kit (coreclr) |
| Python | `pyproject.toml` | — | ✅ | ✅ | Python 인터프리터 · Python 확장 (debugpy) |
| C++ (CMake) | `CMakeLists.txt` | ✅ | ✅ | ✅ | `cmake` + C++ 컴파일러 · C/C++ (auto) 또는 CodeLLDB |
| Go | `go.mod` | ✅ | ✅ | ✅ | Go 툴체인 · Go 확장 (delve) |
| Node.js / TypeScript | `package.json` | ✅ | ✅ | ✅ | Node.js · 내장 js-debug (별도 확장 불필요) |

- Python은 빌드 단계가 없다 — 인터프리터가 직접 실행한다 (Build 버튼 미표시).
- Node.js는 **npm 스크립트**(`<pm> run <script>`)를 실행하므로 빌드/디버그 동작은 스크립트가 정의한다. js-debug는 VS Code에 내장되어 확장 설치가 필요 없다.
- 디버그 확장은 처음 디버그할 때 설치를 안내하며, 사용하는 언어의 툴체인만 설치되어 있으면 된다.

## 2. 설치

### 2.1 요구 사항

- **VS Code 1.90+**
- 사용할 언어의 툴체인이 `PATH`에 있어야 한다: Rust → `rustup`/`cargo` · C# → .NET SDK · Python → Python 인터프리터 · C++ → `cmake` + 컴파일러(MSVC/GCC/Clang) · Go → `go` · Node.js → Node.js와 패키지 매니저(npm/pnpm/yarn)

언제든 **`DevSwitcher: Doctor`** 명령으로 감지된 것과 누락된 것을 확인할 수 있다.

### 2.2 Marketplace에서 설치

Extensions 뷰에서 **DevSwitcher Tools**를 검색하거나:

```bash
code --install-extension lim8603.devswitcher-tools
```

### 2.3 VSIX로 설치

[GitHub Releases](https://github.com/lim8603/dot-tools/releases)에서 `.vsix`를 내려받아:

```bash
code --install-extension devswitcher-tools-1.0.0.vsix
```

## 3. 시작하기

1. 지원 매니페스트(`Cargo.toml`, `*.csproj`, `pyproject.toml`, `CMakeLists.txt`, `go.mod`, `package.json`)가 있는 폴더를 VS Code로 연다.
2. 확장이 자동 활성화되어 워크스페이스를 스캔하고, 상태바 **왼쪽**에 DevSwitcher 칩이 나타난다.
3. 프로젝트 칩을 클릭해 활성 프로젝트를 고르고, 옵션 칩으로 프로파일·타깃 등을 선택한 뒤 Build / Run / Debug 버튼을 누른다.

지원 매니페스트가 하나도 없으면 상태바는 표시되지 않는다(감시는 유지되므로 매니페스트가 생기면 자동 등장). 빈 폴더라면 **`DevSwitcher: New Project…`** 로 새 프로젝트를 만들 수 있다 (§9).

멀티루트 워크스페이스와 Cargo workspace(멤버 패키지)도 지원하며, 프로젝트별 칩 선택 상태는 각각 독립적으로 기억된다. `.vscode/settings.json`이나 `launch.json`은 **필요 없다** — 디버그 구성은 프로그램적으로 생성된다.

## 4. 상태바 구성

| 요소 | 설명 |
| --- | --- |
| `$(repo)` **Project** | 활성 프로젝트. 클릭하면 워크스페이스의 전체 프로젝트(언어 무관)를 QuickPick으로 전환. |
| **옵션 칩** | 언어별 빌드 옵션(프로파일/구성, 아키텍처/타깃, features, Python 환경, CMake 프리셋 등). 클릭해 변경. 필수(required) 칩은 값이 없으면 경고 배경으로 강조된다. |
| `$(symbol-method)` **Target** | 실행/디버그할 바이너리·실행 파일·스크립트. |
| `$(tools)` `$(debug-alt)` `$(play)` | **Build · Debug · Run** 버튼. |
| `$(debug-stop)` **Stop** | 실행/빌드 태스크나 디버그 세션이 활성일 때만 나타남 — 클릭으로 중지. |
| `$(run-all)` **Groups** | Run Group이 정의되어 있을 때 나타남 — 클릭으로 그룹 실행/중지/전체 중지. |
| `$(gear)` | 설정 페이지 열기. |
| `$(warning) Toolchain` | 필수 도구가 누락됐을 때 나타남 — 클릭하면 Doctor 실행. |

### 4.1 언어별 칩 구성

| 언어 | 표시되는 칩 |
| --- | --- |
| Rust | 프로젝트 · 프로파일 · target triple · features · 바이너리 |
| C# | 프로젝트 · configuration · runtime identifier · target framework |
| Python | 프로젝트 · 인터프리터/venv · 스크립트 (Build 버튼 없음) |
| C++ (CMake) | 프로젝트 · 프리셋 · 실행 파일 — `CMakePresets.json`이 있으면 **Preset** 칩이 프로파일/아키텍처 칩을 대체하고 `cmake --preset`으로 컴파일러(MSVC ↔ Clang-CL ↔ GCC)를 전환 |
| Go | 프로젝트 · 패키지 (모듈의 `main` 패키지) |
| Node.js / TypeScript | 프로젝트 · 스크립트 (npm 스크립트) · 패키지 매니저 (npm/pnpm/yarn 자동 감지) |

### 4.2 상태 표현

| 상태 | 상태바 표현 |
| --- | --- |
| 프로젝트 0개 | 칩 전체 미표시 |
| 툴체인 미설치 | 경고 칩 → 클릭 시 Doctor |
| 매니페스트 파싱 실패 | 프로젝트 칩 에러 배경, 마지막 정상 상태로 계속 동작 |
| 필수 칩 미선택 | 경고 배경, 액션 시 해당 QuickPick 먼저 표시 |
| 작업 진행 중 | 액션 버튼 스피너 표시 + 중복 실행 방지 |

## 5. 빌드 / 실행 / 디버그

모든 명령은 명령 팔레트(`Ctrl/Cmd+Shift+P`)의 **`DevSwitcher:`** 카테고리에 있다.

| 명령 | 동작 |
| --- | --- |
| **Build** (`devSwitcher.build`) | 필수 칩 검증 후 활성 프로젝트를 빌드. 실패 시 Problems 패널에 진단 표시(problem matcher). |
| **Run** (`devSwitcher.run`) | 활성 프로젝트 실행 (예: `cargo run`은 빌드 포함). |
| **Debug** (`devSwitcher.debug`) | 필요한 디버그 확장 확인(온디맨드 설치) → 빌드(실패 시 중단) → 실행 파일 경로 해석 → 디버그 세션 시작. |
| **Stop** (`devSwitcher.stop`) | 활성 프로젝트의 실행 중 태스크(개발 서버·워처 등 장기 실행 `run`)를 종료. |
| **Rescan Projects** (`devSwitcher.rescan`) | 폴더 이동·외부 변경 등 감시가 놓친 변경을 강제 재스캔. |

- 빌드/실행은 VS Code **Task API**로 실행되어 종료 코드를 감지하고, Rust(`rustc`)·Go용 problem matcher가 진단을 Problems 패널에 연결한다.
- 실행 인자(run args)는 설정 페이지에서 지정하면 실행/디버그 시 `--` 뒤 프로그램 인자로 전달된다.
- 매니페스트(`Cargo.toml` 등)가 바뀌면 자동으로 감지·갱신된다(500ms 디바운스).

## 6. 키보드 단축키

기본 단축키는 **DevSwitcher 프로젝트가 존재할 때만**(`devSwitcher.hasProjects`) 활성화되어, 무관한 워크스페이스에서 충돌하지 않는다.

| 동작 | Windows / Linux | macOS |
| --- | --- | --- |
| Build | `Ctrl+Alt+B` | `Cmd+Alt+B` |
| Run | `Ctrl+Alt+R` | `Cmd+Alt+R` |
| Stop | `Ctrl+Alt+S` | `Cmd+Alt+S` |
| Debug | `Ctrl+Alt+D` | `Cmd+Alt+D` |
| Switch Project | `Ctrl+Alt+P` | `Cmd+Alt+P` |
| Run Groups | `Ctrl+Alt+G` | `Cmd+Alt+G` |
| Open Settings | `Ctrl+Alt+,` | `Cmd+Alt+,` |

VS Code **Keyboard Shortcuts** 편집기에서 모두 변경할 수 있다 — 설정 페이지의 **General** 탭이 단축키 목록과 해당 편집기 바로가기(DevSwitcher 필터 적용)를 제공한다. VS Code 기본 키(`F5` 디버그, `Ctrl+Shift+B` 빌드 태스크)는 건드리지 않으며, 원하면 `devSwitcher.debug`를 `F5`에, `devSwitcher.build`를 `Ctrl+Shift+B`에 직접 바인딩할 수 있다.

## 7. 설정 페이지

상태바의 `$(gear)` 칩 또는 **`DevSwitcher: Open Settings`**(`Ctrl+Alt+,`)로 연다. 설정 페이지는 에디터 탭 형태의 페이지로, 다음을 제공한다.

- **General 탭** — 기본 단축키 목록과 VS Code Keyboard Shortcuts 편집기 바로가기(DevSwitcher 필터).
- **Project 카드** — 프로젝트별 정보를 카드로 표시한다. (카드의 세부 항목 구성은 기준 문서에 상세 기재 없음 — 미확정)
- **옵션 카탈로그 (호출 구성)** — 컴파일러 플래그, 링커 플래그, 출력 디렉터리, 환경변수, 빌드 전/후(pre/post) 명령을 편집한다. 각 옵션은 설명·예제·허용값이 함께 표시되고(enum은 드롭다운, bool은 토글), 하단에 실제 실행될 명령의 **라이브 미리보기**가 나타난다. 설정은 **(프로젝트 × 프로파일)** 단위로 확장 내부에 저장되며 호출 시점에 주입된다 — 캐노니컬 빌드 파일은 수정되지 않는다(프로파일 목록은 읽기 전용). 이 오버레이는 DevSwitcher 호출에만 적용되며, 수동 터미널 빌드에는 적용되지 않는다(설계된 동작).
- **프로파일 export / import** — 칩 선택과 (프로젝트 × 프로파일) 오버레이를 이식 가능한 `devswitcher.profile.json`으로 저장/불러오기. 명령 **`DevSwitcher: Export Profile`** / **`Import Profile`**로도 수행할 수 있다. projectId는 머신 독립적이어서 다른 클론에서 import하면 존재하는 프로젝트만 반영된다.
- **Run Groups 탭** — Run Group 정의 (§8).

## 8. Run Group

여러 프로젝트를 **의존 순서대로 한 번에** 시작한다 — 예: `auth → api → web`.

### 8.1 정의

설정 페이지 → **Run Groups** 탭에서 그룹 이름을 정하고 드롭다운으로 **프로젝트를 추가**한다. 각 멤버는 카드로 표시되며 **Stage** 번호와 **Ready when** 게이트를 갖는다.

- **Stage**: 같은 스테이지는 동시에 시작하고, 높은 스테이지는 이전 스테이지 전체가 **ready**가 될 때까지 대기한다. `auth (1) → api (2) → web (3)`이면 순서대로, 같은 스테이지의 두 멤버는 병렬로 시작한다.

### 8.2 준비 게이트 (Ready when)

| 게이트 | ready 판정 기준 |
| --- | --- |
| **process start** (기본) | 멤버 프로세스가 시작되는 즉시 (설정 불필요, 가장 빠름) |
| **port open** | `localhost:<port>` TCP 연결이 성공할 때 |
| **HTTP status** | `GET <url>`이 기대 상태 코드(기본 `200`)를 반환할 때 |

port/HTTP 게이트는 통과하거나 멤버의 **timeout**이 지날 때까지 폴링한다. timeout 안에 ready가 되지 못한 멤버는 그룹 시작을 **중단**시키고, 이미 시작된 멤버들을 되돌려 종료한다. 오래 걸리는 준비 대기는 진행 알림(progress notification)에서 **취소**할 수 있다.

### 8.3 실행 / 중지

- 그룹 카드의 **Run**/**Stop** 버튼, 상태바 `$(run-all)` 런처, 또는 **`DevSwitcher: Run Groups…`**(`Ctrl+Alt+G`) — 이 메뉴는 **Stop all**도 제공한다.
- 개별 명령 `DevSwitcher: Run Group…` / `Stop Run Group…`도 명령 팔레트에서 쓸 수 있다.
- 이미 실행 중인 멤버(단독 실행이든 다른 그룹이든)는 ready로 간주하고 건너뛰므로 나머지 그룹은 정상 시작된다.

## 9. New Project 마법사

매니페스트가 없는 빈 폴더에서도 프로젝트를 시작할 수 있다.

1. **`DevSwitcher: New Project…`**(`devSwitcher.newProject`)를 명령 팔레트에서 실행한다 (수동 호출 전용 — 자동 제안 없음).
2. **부모 폴더 선택** — 기본은 워크스페이스 루트이며 `services/`, `apps/` 같은 하위 폴더도 자유롭게 선택할 수 있다 (워크스페이스 내부로 제한).
3. **언어 선택** → **이름 입력**.
4. 해당 언어의 **네이티브 도구가 기본 템플릿을 생성**한다: Rust → `cargo new` · C# → `dotnet new console` · C++ → CMake 최소 템플릿(`CMakeLists.txt` + `main`) · Python → 기본 `pyproject.toml`. (Go·Node.js 템플릿의 세부 생성 방식은 기준 문서에 명시 없음 — 미확정)
5. 생성된 매니페스트를 감시자가 자동 감지하여 프로젝트 스위처에 즉시 등장한다.

네이티브 도구가 없으면 Doctor / 온디맨드 안내로 연결된다.

## 10. Doctor 진단

**`DevSwitcher: Doctor (environment diagnostics)`**(`devSwitcher.doctor`)는 활성 어댑터의 전제조건(툴체인·디버그 확장)을 일괄 점검하고, 항목별 해결 액션을 QuickPick으로 제시한다.

- **원칙 — 우아한 성능 저하**: 누락된 것에 의존하는 기능만 비활성화하고, 복구 경로를 항상 제시한다.
- **해결 3단계**: ① 완전 자동(확장 설치, `rustup target add`) → ② 반자동(툴체인 설치 명령 대행) → ③ 안내만(WSL 본체, Docker Desktop 등).
- **진입점**: 명령 팔레트, 상태바 `$(warning) Toolchain` 경고 칩 클릭, 온디맨드 설치 취소 시.

## 11. 확장 설정 (settings)

VS Code 설정(`Ctrl+,`)의 **DevSwitcher** 섹션:

| 설정 키 | 기본값 | 설명 |
| --- | --- | --- |
| `devSwitcher.statusBar.compact` | `false` | 칩을 아이콘만으로 표시 (값은 호버/클릭 시). 좁은 창에 유용. 명령 **`DevSwitcher: Toggle Compact Status Bar`**로도 전환 가능. |
| `devSwitcher.statusBar.selectedOnly` | `false` | 값이 있는 칩만 표시 — 값이 없는 선택(optional) 칩은 숨김 (필수 칩은 항상 표시). |
| `devSwitcher.cmake.debugger` | `auto` | CMake 어댑터가 쓸 디버거. `auto`는 컴파일러에서 자동 판별(MSVC → cppvsdbg, GCC → cppdbg+gdb, Clang → cppdbg+lldb), `cpptools`/`codelldb`로 강제 지정 가능. |

## 12. 트러블슈팅 · Known Limitations

### 12.1 문제 해결

| 증상 | 원인 | 해결 방법 |
| --- | --- | --- |
| 상태바에 칩이 안 보임 | 지원 매니페스트가 워크스페이스에 없음 | 매니페스트 확인, 또는 `DevSwitcher: New Project…`로 생성. 매니페스트가 생기면 자동 등장 |
| `$(warning) Toolchain` 경고 칩 | 필수 툴체인 미설치 | 칩 클릭 → Doctor의 해결 액션 수행 |
| 칩이 경고 배경으로 강조됨 | 필수 칩 값 미선택 | 칩 클릭해 선택 (액션 실행 시 QuickPick이 먼저 뜸) |
| 프로젝트 칩이 에러 배경 | 매니페스트 파싱 실패 | 파일 수정 후 저장하면 재시도. 마지막 정상 상태로는 계속 동작 |
| 폴더 이동·VCS 체크아웃 후 목록이 안 맞음 | 파일 감시가 놓친 외부 변경 | **`DevSwitcher: Rescan Projects`** 실행 |
| 디버그 시작 시 확장 설치 안내 | 디버그 확장 미설치 | 안내를 수락해 온디맨드 설치 (Node.js는 내장 js-debug라 불필요) |
| Run Group 시작이 중단됨 | 멤버가 timeout 내 ready 실패 | 게이트의 port/URL·timeout 값 확인. 이미 시작된 멤버는 자동 정리됨 |
| 터미널에서 직접 빌드하면 설정한 옵션이 안 먹음 | 오버레이는 DevSwitcher 호출에만 주입됨 | 설계된 동작 — DevSwitcher의 Build/Run/Debug를 사용 |
| WSL에서 빌드가 매우 느림 | `/mnt/...`(9p 파일시스템) 경로 | 저장소를 WSL 파일시스템 내부로 이동 |

### 12.2 Known limitations (v1.0.0)

- **한 창 = 한 실행 환경.** VS Code 창은 단일 실행 환경에 바인딩된다 — 칩 전환으로 Windows MSVC ↔ WSL GCC를 오갈 수 없다. Windows 창과 WSL 창을 각각 열어 사용한다.
- **WSL에서 `/mnt/...` 경로는 느리다** — 저장소를 WSL 파일시스템 안에 두는 것을 권장.
- **WSL 수동 검증 미수행 (Known Issue, v1.0.0).** 확장은 remote-safe(`workspace.fs`, workspace 측 실행)로 구현됐지만, 이번 릴리즈에서 WSL 전용 수동 테스트 패스는 수행되지 않았다. WSL 관련 문제를 겪으면 [이슈 등록](https://github.com/lim8603/dot-tools/issues)을 부탁한다.

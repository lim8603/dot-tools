## 1. 개요 — UI 구성 요소 총괄

DevSwitcher Tools의 사용자 대면 UI는 다음으로 구성된다. 모든 화면은 언어 중립적으로,
어댑터가 선언한 `ChipDescriptor[]` / `OptionSpec[]` / 진단 프로브만으로 렌더링된다(ADR-003, INV-2).

| 화면 | 소스 | 형태 |
|------|------|------|
| 상태바 | `src/ui/statusBar.ts` · `src/ui/statusBarFormat.ts` | VSCode StatusBarItem (좌측 정렬) |
| 설정 페이지 | `src/ui/settingsPanel/` (`settingsPanel.ts` · `html.ts` · `projectCard.ts` · `shortcuts.ts`) | WebviewPanel (에디터 탭) |
| 칩 선택 | `src/ui/picks.ts` | QuickPick |
| 환경 진단 | `src/ui/doctorPick.ts` | QuickPick |
| 새 프로젝트 마법사 | `src/ui/newProjectWizard.ts` | 폴더 선택 대화상자 + QuickPick + InputBox |

## 2. 상태바 (StatusBarController)

### 2.1 레이아웃과 칩 배치

좌측 정렬. 우선순위(priority)는 `1000 − order`로 계산되어 값이 클수록 왼쪽에 배치된다.
현재 구현의 좌→우 순서는 다음과 같다.

```
[⚠ Toolchain]  $(repo) hello  $(layers) dev  …(어댑터 칩들)…  [Build][Debug][Run][Stop][Groups][⚙]
  (경고 시)      프로젝트 칩      어댑터 선언 칩                    후행 컨트롤(고정 순서)
```

- **프로젝트 칩**(`$(repo) <이름>`)이 일반 렌더의 가장 왼쪽. 클릭 → `devSwitcher.switchProject`.
- **어댑터 칩**: 활성 어댑터의 `ChipDescriptor[]` 순서대로 배치. 클릭 → `devSwitcher.pickChip`(QuickPick).

  | 어댑터 | 표시되는 칩 |
  |---|---|
  | Rust (Cargo) | Profile · Architecture · Features · Target |
  | C++ (CMake) | Preset **또는** Profile+Architecture (`appliesTo` 상호 배타) · Target |
  | **Visual Studio** *[v1.2.0]* | **Configuration**(profile 슬롯) · **Platform**(architecture 슬롯) |
  | C# (.NET) | Profile · Architecture · Target |
  | Go | Target |
  | Node.js / TS | Script · Package Manager |
  | Python | Environment · Target (Build 버튼 없음 — `actions.build: false`) |

  Visual Studio 칩이 `profile`/`architecture`라는 **기존 슬롯 id를 그대로 쓰는 것**이 요점이다. 라벨만
  Configuration/Platform으로 바뀔 뿐 상태바·QuickPick·설정 페이지 코드는 손대지 않았다 — ADR-003의
  선언적 칩 모델이 7번째 어댑터에서도 성립함을 보인 사례다.
- **후행 컨트롤 고정 순서** *[구현 반영 — 설계의 Build·Debug·Run 3버튼에서 확장됨]*:
  Build(900) · Debug(901) · Run(902) · **Stop(903)** · **Run Group 런처(904)** · **설정 기어(905)**.
  - Build 버튼은 `adapter.actions.build`가 false인 어댑터(예: 인터프리터 언어)에서는 숨김.
  - **Stop 버튼**(`$(debug-stop)`, F16): 활성 프로젝트에 실행 중인 task/디버그 세션이 있을 때만 표시. 클릭 → `devSwitcher.stop`.
  - **Run Group 런처**(`$(run-all)`, C-6/MS-013): 그룹이 1개 이상 정의된 경우에만 표시. 실행 중이면 `$(run-all) N`(실행 중 그룹 수). 워크스페이스 수준이므로 프로젝트 전환·프로젝트 없음 상태에서도 유지. 클릭 → `devSwitcher.groups`.
  - **설정 기어**(`$(gear)`): 클릭 → `devSwitcher.openSettings`.
- **Toolchain 경고 칩**(`$(warning) Toolchain`, E1/§5.4) *[구현 반영]*: 툴체인 문제 감지 시 최좌측(priority 1001)에 `warningBackground`로 표시. 프로젝트가 하나도 활성화되지 못한 상태에서도 유지되며, 클릭 시 Doctor 실행(`devSwitcher.doctor`).

### 2.2 칩 표시 규칙

- 값이 있는 칩: 어댑터의 `format()` 결과, 없으면 `defaultChipFormat()` 폴백 —
  다중 선택 값은 빈 배열 → `default`, 1~2개 → 이름 나열, 3개 이상 → `N features`.
- 미선택 칩: 어댑터가 `unsetText`를 선언하면 그 값(예: architecture의 `default` = 호스트 타깃),
  아니면 `(라벨)` 프롬프트 형태. *[구현 반영 — `unsetText`는 설계 이후 추가]*
- `required` 칩이 미선택이면 `statusBarItem.warningBackground` 배경.
- 매니페스트 파싱 오류 시 프로젝트 칩에 `statusBarItem.errorBackground` 배경.
- 프로젝트별 비적용 칩(`appliesTo`, TASK-041)은 렌더에서 제외 — 예: CMake 프리셋 활성 시 profile/architecture 칩 대신 Preset 칩. *[구현 반영]*
- 툴팁: `라벨: 값` (다중 선택은 쉼표 나열), 미선택은 라벨(또는 `라벨: unsetText`).

### 2.3 표시 모드 (Compact / Selected-only) *[구현 반영 — 설계 이후 추가]*

| 설정 | 동작 |
|------|------|
| `devSwitcher.statusBar.compact` | 칩의 값 텍스트를 생략하고 아이콘만 표시(hover/클릭으로 값 확인). 좁은 창 대응 — VSCode가 상태바 폭 신호를 주지 않아 자동이 아닌 사용자 토글. |
| `devSwitcher.statusBar.selectedOnly` | 값이 비어 있는(blank) 선택형 칩 숨김. `required` 칩은 항상 유지. |

두 설정 모두 VSCode 설정(Global)이며 설정 페이지 General 탭에서도 토글 가능(§3.9).
`devSwitcher.toggleCompact` 명령으로도 전환.

### 2.4 상태·경고 표시

- 액션 실행 중: 해당 버튼이 `$(sync~spin)` 스피너로 바뀌고 클릭 불가(command 제거). task 종료 시 다음 render에서 복원.
- 프로젝트 없음/유휴 상태: 프로젝트 UI 전체 숨김(`hideAll`). 단 Toolchain 경고 칩과 Run Group 런처는 각자의 소유 메서드(`setToolchainWarning`/`setGroups`)가 표시 여부를 관리하므로 유지.

## 3. 설정 페이지 (SettingsPanel, WebviewPanel)

### 3.1 진입과 패널 속성

- 진입: 명령 `DevSwitcher: Open Settings`(`devSwitcher.openSettings`), 상태바 기어, 단축키 `Ctrl+Alt+,`.
- `WebviewPanel`(viewType `devSwitcherSettings`, 제목 "DevSwitcher Settings"), 에디터 탭으로 열림. **단일 인스턴스** — 이미 열려 있으면 reveal.
- `retainContextWhenHidden: false` — 숨겨지면 다음 표시 시 상태 재요청(메모리 절약).
- CSP: `default-src 'none'; style-src ${cspSource} 'nonce-…'; script-src 'nonce-…'` — 외부 리소스 금지, 인라인 스크립트/스타일은 로드마다 생성되는 nonce로만 허용.
- 원칙(ADR-012, 상세설계서 §10.1): 페이지는 값을 자체 저장하지 않는다. 캐노니컬 정의(계층②)는 읽기 전용,
  호출 구성 오버레이(계층③)만 `(프로젝트×프로파일)`별 `workspaceState`에 저장.
- 색·폰트는 전부 VSCode 테마 변수(`--vscode-*`) 기반 — 라이트/다크 자동 대응.

### 3.2 전체 레이아웃

```
┌─ DevSwitcher Settings ─────────────────────────────────────────────┐
│ Project [ hello ▼ ]      Cargo (Rust)  ·  profile: dev             │ ← 상단 컨텍스트 바
├──────────────┬─────────────────────────────────────────────────────┤
│ Project      │                                                     │
│ Features     │                                                     │
│ Profile      │            (선택된 탭 내용)                          │
│ Invocation   │                                                     │
│ Run Groups   │                                                     │
│ General      │                                                     │
└──────────────┴─────────────────────────────────────────────────────┘
   좌측 탭(160px)                    우측 디테일
```

- 상단 컨텍스트 바: 활성 프로젝트 드롭다운 + 어댑터 표시명·활성 프로파일 라벨.
- *[구현 반영]* 설계의 상단 `[Refresh]` 버튼은 제거됨 — 외부 변경(상태바 칩 픽, 매니페스트 재스캔) 시
  확장이 `refresh()`로 최신 `state`를 자동 재전송하므로 수동 새로고침이 불필요.

### 3.3 탭 구성과 표시 조건

*[구현 반영]* 설계(Project·Profile·Features·Invocation·General 5탭) 대비 **Run Groups 탭이 추가**되고
순서가 변경되었다. 현재 구현의 탭 목록·조건:

| 탭 | 표시 조건 | 저장 대상 |
|----|-----------|-----------|
| Project | 항상 | `activeProjectId` (카드 클릭 = 프로젝트 전환) |
| Features | 어댑터 `chips`에 `features` 칩 존재 | 선택 = StateStore, 정의 = 읽기 전용 |
| Profile | 어댑터 `chips`에 `profile` 칩 존재 | v1 읽기 전용 (편집은 v2, ADR-011) |
| Invocation | `configCategories`가 비어 있지 않음 | InvocationConfig (프로젝트×프로파일 오버레이) |
| Run Groups | **항상** (워크스페이스 수준, 프로젝트 무관) | RunGroup (workspaceState) |
| General | 항상 | 상태바 표시 설정(VSCode 설정 Global) |

- 탭 표시는 칩/카테고리 선언만으로 결정 — 어댑터 추가 시 이 코드는 무변경(§10.2 유지).
- 활성 프로젝트가 없을 때: Project·Run Groups 탭은 정상 렌더(카드에서 프로젝트 선택 가능),
  그 외 탭은 "No project selected…" 빈 상태 안내를 표시.

### 3.4 Project 탭 — 프로젝트 카드 *[구현 반영 — 세션 #014(B-2)에서 카드형으로 재설계]*

감지된 프로젝트 1개당 카드 1장("Detected projects"). 카드 전체가 클릭 대상이며, 클릭 시 해당 프로젝트로 전환.
활성 카드는 포커스 색 테두리 + `active` 배지.

```
┌───────────────────────────────────────────────┐
│ hello  [Cargo (Rust)] [active]                │  ← 이름 + 어댑터 표시명 배지 + 활성 배지
│ crates/hello/Cargo.toml                       │  ← 매니페스트 상대 경로
│ ✓ toolchain  cargo 1.83.0                     │  ← 툴체인 상태 (Doctor 프로브에서 파생)
│ profile  dev                                  │  ← 유효 활성 프로파일 (미저장 시 기본값 폴백)
│ Target: hello (3)   Features: — (2)  …        │  ← 칩별 요약: 현재 값 + 선택 가능 항목 수 배지
└───────────────────────────────────────────────┘
```

- **툴체인 상태**: 어댑터 Doctor 프로브 중 primary(critical) 검사를 ✓(ok)/✗(error)/!(warn)/?(unknown)로 축약,
  버전 문자열을 라벨로 표기(예: `cargo 1.83.0`, `cargo not found`). 프로브가 없는 스텁 어댑터는 `?` + 표시명.
  결과는 패널 수명 동안 어댑터별 캐시(편집 반응성 확보) — 패널을 닫았다 열면 재검사.
- **칩 요약**: 값 없으면 `—`. 항목 수 배지는 `secondary` 항목(예: 미설치 rustup 타깃 ~100개) 제외.
  profile 칩은 칩 행이 아닌 별도의 `profile` 라인으로 표기.
- 프로젝트가 하나도 없으면 매니페스트(Cargo.toml, package.json, …)를 가진 폴더를 열라는 안내 문구.
- 모든 필드는 선언적 어댑터 데이터(displayName·chips·프로브)에서 파생 — 언어 지식 없음(INV-2).

### 3.5 Features 탭

- 어댑터가 선언한 feature 항목의 **체크박스 리스트**. 각 항목: 라벨 + (설명).
- 체크 변경 즉시 `setChipValue`로 전체 선택 집합 전송 → 상태바와 실시간 동기화.
- 선언된 feature가 없으면 "No features declared." 안내.

### 3.6 Profile 탭

- 프로파일 목록(읽기 전용) — 제목에 "(read-only)" 명시. 각 행: 라벨 + 설명 배지, 활성 행에 `active` 배지.
- 하단 안내: 프로파일은 프로젝트 빌드 파일에서 오며 DevSwitcher는 전환만 하고 편집하지 않는다.
- 커스텀 프로파일 생성·스칼라 국소 편집은 v2(ADR-011).

### 3.7 Invocation 탭 — 옵션 카탈로그

*[구현 반영]* 설계의 3단 마스터-디테일(카테고리 → 옵션 → 에디터) 대신, **단일 열 스크롤 폼**으로 구현됨 —
카테고리를 `h3` 섹션 헤더로 나열하고 각 옵션의 에디터·설명을 그 자리에 인라인 배치한다.

```
Invocation config  · profile: dev
──────────────────────────────────
compiler
  Optimization level
  [ 3 ▼ ]
  How much the compiler optimizes…          ← description
  e.g. 3 · injects --config profile… · docs ↗   ← meta 라인
  … (옵션 반복)
linker / output / env
  … (카테고리 반복)
runArgs
  [ --verbose --input data.txt          ]
  argv: [--verbose, --input, data.txt]      ← parseArgsLine 토큰화 미리보기
buildEvent
  Pre-build  [textarea, 한 줄당 한 명령]
  Post-build [textarea]
──────────────────────────────────
Command preview
  pre:    cargo fmt
  build:  RUSTFLAGS="…" cargo build -p hello --profile dev --config …
  run:    cargo run -p hello --profile dev -- --verbose --input data.txt
  post:   cp target/release/app dist/
```

- **옵션 에디터 타입** (`OptionSpec.type`으로 결정):

  | type | 에디터 | 비고 |
  |------|--------|------|
  | `enum` | 드롭다운(`allowedValues`) | 유효값 = 저장값, 없으면 옵션 기본값 표시 |
  | `bool` | 체크박스 | |
  | `int` | 숫자 입력 | 비우면 해제(clearOption) |
  | `string` | 텍스트 입력 | 비우면 해제 |
  | `stringList` | textarea (한 줄당 1항목) | blur 시 커밋 *[구현 반영 — 설계의 "여러 줄"을 구체화]* |

- 각 옵션은 라벨 아래에 **설명**(`description`)과 **meta 라인**(`e.g. 예제` · `injects 주입 형태` · `docs ↗` 링크)을
  함께 표기 — 옵션을 모르는 개발자 교육 목적(ADR-012). 예제는 placeholder가 아닌 별도 라인(입력값으로 오인 방지).
- **runArgs**: 카탈로그가 아닌 자유 편집 1줄 입력 → 순수 `parseArgsLine()` 토큰화 결과를 `argv:` 라인으로 미리보기.
- **buildEvent** *[구현 반영 — F21로 추가된 카테고리]*: Pre-build/Post-build textarea, 한 줄당 한 셸 명령.
  프로젝트 디렉터리에서 사용자 셸로 실행(NFR-002a).
- **Command preview** *[구현 반영 — 설계의 단일 라인에서 확장]*: `pre:` / `build:` / `run:` / `post:` 멀티라인.
  실제 Task의 ProcessExecution에서 역산하며, env로 주입되는 옵션(RUSTFLAGS 등)은 `VAR=val` 셸 접두어로 표기.
  스텁 어댑터는 해당 라인 생략.
- `configCategories`에 없는 카테고리는 섹션 자체가 숨김 — 예: Python은 `actions.build=false`라
  Compiler/Linker/Output 없이 Env·Run args만 표시(리트머스, INV-2).

### 3.8 Run Groups 탭 — 그룹·멤버 카드·준비 게이트 *[구현 반영 — 설계 이후 신설(C-6/MS-013), 세션 #014(MS-018)에서 재설계]*

여러 프로젝트를 의존 순서(예: auth → api → web)로 함께 시작하는 워크스페이스 수준 기능.

```
Run groups
  (설명문)
  [ New group name        ] [Add group]

  ▸ my-stack   [3 member(s)] [running] [⚠ 1]     ← 그룹 행 (클릭 = 선택)
  ▸ other      [1 member(s)]

  Editing: my-stack
  [ my-stack           ] [Run|Stop] [Delete]      ← 이름 변경 + 실행/중지 + 삭제
  ⚠ (검증 문제 나열)

  Members [3]
  ┌─────────────────────────────────────────────────┐
  │ auth  [node]            Stage [1]  [Remove]     │  ← 멤버 카드 (Stage 순 정렬)
  │ ─────────────────────────────────────────────── │
  │ Ready when [port open ▼] [3000]  timeout(s)[30] │  ← 준비(readiness) 편집기
  └─────────────────────────────────────────────────┘
  … (멤버 카드 반복)

  Add a project [ Select… ▼ ]                       ← 미포함 프로젝트만 나열
  (힌트: 같은 Stage는 병렬, 높은 Stage는 하위 Stage ready 후 시작)
```

- **그룹 목록**: 행마다 이름 + `N member(s)` 배지 + 실행 중이면 `running` 배지 + 검증 문제 수 `⚠ N` 배지.
  상단에 새 그룹 이름 입력 + `Add group` 버튼(빈 이름 → "New group").
- **그룹 편집기**: 이름 입력(blur 시 rename), 실행 상태에 따라 `Run` 또는 `Stop` 버튼, `Delete` 버튼
  (실행 중 삭제 시도 시 경고 알림 "stop the run group before deleting it").
- **멤버 카드** (세션 #014): 멤버 1명당 카드 1장, **Stage 오름차순 정렬**(동률은 이름순).
  카드 헤더 = 프로젝트명 + 어댑터 id 배지 + `Stage` 숫자 입력(1 이상) + `Remove` 버튼.
- **준비 게이트(Ready when) 편집기** (MS-018): 카드 하단 구분선 아래, 멤버별 `ReadinessProbe` 편집.

  | 종류 | 추가 필드 | 의미 |
  |------|-----------|------|
  | `process start` | 없음 | 프로세스 기동 = ready (기본값, probe 미저장) |
  | `port open` | port (1–65535) + timeout(s) | 포트가 열리면 ready |
  | `HTTP status` | URL + 기대 status(선택) + timeout(s) | HTTP 응답(기본 2xx/지정 status)이면 ready |

  종류 전환 시 합리적 기본값 시드(port 3000 / `http://localhost:3000/health`, timeout 30s).
  빈 port/URL은 그대로 저장되어 검증 경고(⚠)로 표면화 — 게이트가 조용히 사라지지 않는다.
- **Add a project 드롭다운** (세션 #014): 아직 그룹에 없는 프로젝트만 `이름 (어댑터)` 형태로 나열 —
  전체 프로젝트 체크리스트 대신 드롭다운으로 목록을 깔끔하게 유지. 감지된 프로젝트가 없으면 안내 문구.
- 하단 힌트: 같은 Stage는 병렬 실행, 높은 Stage는 모든 하위 Stage가 ready된 후 시작.

### 6.1 화면에 드러나지 않는 v1.2.1 변경 *[v1.3.0 추가]*

설정 페이지는 **칩 목록을 그리는 행위 자체가 부작용을 일으키지 않도록** 바뀌었다. 화면 결과물은 거의
같아 보이지만, 카드 렌더·칩 뷰 구성·카드 기본값 조회가 모두 `probe: false`로 어댑터에 묻는다 — 이전에는
설정 페이지를 열거나 카드를 클릭하는 것만으로 CMake가 구성되어 소스 디렉토리에 빌드 트리가 생겼다.

UI는 여전히 언어를 모른다(INV-2). "무엇이 비싼 작업인가"는 어댑터가 판단하고, UI는 "지금은 부작용 없이
답해 달라"만 전달한다.

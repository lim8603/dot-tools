## 1. 개요

DevSwitcher Tools는 여러 언어 프로젝트(Rust · C++/CMake · C++/Visual Studio · C# · Python · Go · Node.js/TypeScript)를 하나의 VSCode 상태바 UX로 전환·빌드·실행·디버그하는 VSCode 확장이다. 본 문서는 v0.1.0(2026-08-16)부터 v1.3.0(2026-08-25)까지의 전체 릴리즈 이력을 기록한다.

- 사실 관계는 `CHANGELOG.md`(영문 원본)를 기준으로 하며, CHANGELOG에 없는 사실은 추가하지 않는다.
- 각 릴리즈의 관련 Milestone은 `.cowork/04_implementation/milestone_registry.md`를 기준으로 한다.
- **배포 방식:** v0.1.0~v0.8.0은 `.vsix` + git 태그로만 배포되었고, v1.0.0부터 Visual Studio Marketplace(`lim8603.devswitcher-tools`)와 GitHub Release로 배포된다.
- **Breaking Change:** 전 릴리즈 공통 없음 (CHANGELOG 기준 기록된 Breaking Change 없음).

## 2.1 v1.3.0 — 정리 기능과 스캔 제어 (2026-08-25)

### 핵심 요약

v1.2.1이 남긴 절반을 마무리한 릴리즈다. v1.2.1은 새 빌드 트리가 **생기는 것**을 막았지만 **이미 생긴 것**은 지우지 못했고, 애초에 그 트리를 스캔에서 빼는 방법도 없었다.

### 신규 기능

- **Clean** (`devSwitcher.clean`) — 빌드 산출물 제거. `cargo clean` · `cmake --build … --target clean` · `MSBuild /t:Clean` · `dotnet clean` · `go clean`. Node·Python은 표준 clean 명령이 없어 제외.
- **Delete Build Tree…** (`devSwitcher.deleteBuildTree`) — 빌드 디렉토리 자체를 삭제. v1.2.1 이전에 벤더 트리·서브모듈에 생긴 `build/`를 원상복구하는 수단이다. 삭제 전 전 경로를 나열하고, 워크스페이스 밖·프로젝트 소스 디렉토리는 거부하며, 가능한 플랫폼에서는 휴지통을 쓴다. Rust·CMake·.NET 지원(Go는 모듈 밖에 쌓고, Visual Studio는 출력 경로를 추측하지 않는다).
- **`devSwitcher.scan.exclude`** — 스캔이 건너뛸 폴더. User·Workspace 값은 **합집합**이며(제외 규칙은 가산적이므로 프로젝트 설정이 개인 규칙을 지우지 않는다), `!` 재포함은 지원하지 않는다.
- **`devSwitcher.cmake.configureOnSelect`** (기본 `false`) — 선택만 해도 구성해서 타깃 목록을 미리 채우는 opt-in. 기본값이 false인 것이 핵심이다 — true가 기본이면 v1.2.1이 고친 결함이 그대로 돌아온다.

### 개선 / 수정

- **비어 있는 칩 목록이 이유를 말한다.** v1.2.1 이후 한 번도 빌드하지 않은 CMake 프로젝트는 타깃 목록이 없고, 설정 페이지는 그것을 `0`으로 그렸다 — 고장처럼 보인다. 이제 "not listed yet"과 함께 목록을 채우려고 빌드·구성을 하지 않는다는 설명을 표시한다.
- **프로젝트 전환이 프로세스를 띄우지 않는다.** v1.2.1이 만든 "아는 것만 답하라" 계약을 CMake만 지키고 있었다. 전환·설정 페이지 렌더·재스캔 정합성 패스가 여전히 `dotnet msbuild` · `cargo metadata` · `rustup target list` · `go list`를, 그리고 가장 심하게는 **후보 인터프리터마다 하나씩 Python 프로브**를 띄우고 있었다. 전부 캐시에서 답하도록 바꿨다. 이들은 파일을 만들지 않았으므로(빈 사본에서 명령을 실행해 확인) 결함 수정이 아니라 속도·정합성 개선이다. `rustup target list`에는 캐시가 아예 없었다 — 이제 있다.

### 알려진 이슈

- Visual Studio 어댑터는 **빌드 트리 삭제를 제공하지 않는다.** MSBuild 출력이 `$(Platform)/$(Configuration)`과 솔루션 레벨로 갈리고 속성으로 재지정될 수 있어, 추측이 틀렸을 때의 대가가 지워진 디렉토리이기 때문이다. Clean은 정상 동작한다.
- Node·Python은 Clean을 지원하지 않는다. Node의 `clean` 스크립트는 프로젝트마다 있고 없고가 갈리는데, 어댑터의 능력 선언이 정적이라 표현할 수 없다.

## 2.2 v1.2.1 — 보기만 해도 구성되던 문제 (2026-08-25)

### 핵심 요약

실사용 제보에서 출발했다 — "서브모듈 10개짜리 읽기 전용 저장소에서 CMake가 빌드 파일을 쏟아낸다."

### 수정

- **프로젝트를 보는 행위가 더 이상 구성을 유발하지 않는다.** 타깃 목록을 얻으려면 구성된 빌드 트리가 필요한데, 여러 경로가 사용자가 요청하지도 않은 그 목록을 물었다 — 그중 최악은 **활성화 시점과 매 재스캔마다, 저장된 상태가 있는 모든 프로젝트에 대해** 도는 정합성 패스였다. 결과적으로 `cmake -S … -B <project>/build`가 소스 디렉토리에 빌드 트리를 썼고, 벤더 트리나 git 서브모듈에서는 읽기 전용으로 다루는 저장소에 우리 파일이 로컬 변경으로 나타났다. 활성화·재스캔·프로젝트 전환·설정 페이지 열기·프로젝트 카드 클릭이 모두 부작용 없는 동작이 되었다. 타깃 피커를 열거나 빌드/실행/디버그를 실행하면 여전히 구성한다 — 그것은 명시적 요청이다.
- **프로젝트 목록이 뒤바뀌지 않는다.** 워크스페이스 스캔 결과를 파일 검색이 반환한 순서 그대로 썼는데 그 순서는 보장되지 않으며 실제로 달라진다. 사용자가 읽는 도중 스위처와 설정 페이지에서 항목이 움직였다. **v1.0.0부터 잠복해 있던 버그**다. 이제 경로순으로 정렬한다.

> 이 릴리즈는 새로 생기는 빌드 트리를 막을 뿐이다. **이미 있는 것은 지우지 않는다** — v1.3.0의 Delete Build Tree가 그 역할을 한다.

## 3. v1.2.0 — Visual Studio 지원 (2026-08-19)

### 3.1 핵심 요약

- **7번째 툴체인: C++ (Visual Studio).** 네이티브 `.sln`/`.slnx` 솔루션과 `.vcxproj` C++ 프로젝트가 동일한 상태바 UX에 합류(Windows). MSBuild를 확장이 직접 구동한다.
- 관련 Milestone: MS-022 (v1.2.0 — Visual Studio 어댑터 + 언어별 enable + 아이콘 리프레시)

### 3.2 신규 기능

- **C++ (Visual Studio) 어댑터** — 솔루션이 루트 항목(빌드=전체 빌드), 각 `.vcxproj`가 하위 항목으로 표시되며 **Configuration**·**Platform** 칩을 가진다. 빌드는 **MSBuild** 직접 구동(`vswhere`로 발견 — Visual Studio·Build Tools 포함, PATH 폴백), 실행/디버그 경로는 MSBuild 자체 평가(`-getProperty:TargetPath`, MSBuild 17.8+), 디버그는 `cppvsdbg`. 라이브러리 프로젝트(static/dynamic)는 빌드만 되고 실행/디버그 시 안내 토스트가 표시된다. **CMake VS 제너레이터가 생성한 솔루션/프로젝트는 자동 제외**(CMakeCache.txt 마커)되어 CMake 어댑터와 충돌하지 않으며, 솔루션 안의 C# 프로젝트는 기존대로 .NET 항목으로 표시된다.
- **언어별 표시 필터** — `devSwitcher.languages.enabled`(설정 페이지 **General** 탭 체크박스): 사용하지 않는 언어를 끄면 해당 프로젝트가 스위처에서 숨고 스캔도 생략된다. 빈/무효 목록은 전체 언어로 동작(fail-open).

### 3.3 개선 / 수정

- **확장 아이콘** — 플랫 벡터 디자인으로 교체.
- **차단 토스트 문구 축약** — 라이브러리/솔루션 실행 차단 안내가 한 줄에서 잘리던 문제로 문구를 짧게 정리.

### 3.4 알려진 이슈

- **TC-11 — WSL/Remote 수동 검증 미수행** (v1.0.0에서 이월, 변동 없음). README *Known limitations* 참조.
- Visual Studio 지원은 Windows 전용이며, 실행/디버그 경로 해석은 MSBuild 17.8+가 필요하다(빌드는 구버전에서도 동작).

## 4. v1.1.0 — 실사용 피드백 1차 (2026-08-19)

### 4.1 핵심 요약

- **첫 실사용 피드백 릴리즈.** 실무 사용에서 보고된 7건을 반영 — CMake 중첩 프로젝트의 Visual Studio식 계층 표시, 라이브러리 타겟 지원, 런그룹 멤버 디버그 기동, 설정 페이지 안정화, 아이콘 수정.
- 관련 Milestone: MS-021 (v1.1.0 실사용 피드백)

### 4.2 신규 기능

- **CMake 중첩 하위 프로젝트** — `project()` 루트 아래에서 타겟을 선언한 `add_subdirectory` 디렉토리를 **인덴트된 하위 프로젝트**로 표시(프로젝트 스위처·설정 Project 탭·설정 드롭다운). 하위 프로젝트는 루트의 빌드 트리로 configure/build 되며, **Target** 선택은 자기 디렉토리의 타겟으로 스코프된다.
- **라이브러리 타겟** — Target 선택에 static/shared/module 라이브러리가 주석("static library" 등)과 함께 표시되어 단독 빌드가 가능하다. 라이브러리 타겟의 실행/디버그는 Visual Studio처럼 안내 토스트로 차단된다(*builds, but cannot run*).
- **All targets** — 루트 CMake 프로젝트의 Target 선택에 **All targets** 항목 추가(`--target` 없는 `cmake --build` = 트리 전체 빌드). 이 상태의 실행/디버그는 단일 실행 타겟 선택을 안내한다.
- **런그룹 멤버 디버그 기동** — 멤버 카드의 **Launch** 모드(Run / **Debug**): Debug 멤버는 그룹 기동 시 해당 툴체인의 디버거로 시작되고, 준비 게이트·그룹 teardown이 동일하게 적용된다(그룹 중지 시 디버그 세션도 종료).
- **라이브러리 표시 옵션** — `devSwitcher.projects.showLibraries`(기본 켜짐, General 탭): 끄면 라이브러리 전용 하위 프로젝트와 라이브러리 타겟을 목록에서 숨긴다.
- **Switch Target 단축키** — `Ctrl/Cmd+Alt+T`로 활성 프로젝트의 타겟 선택 열기(Node는 npm script 선택).

### 4.3 개선 / 수정

- **설정 페이지 공백 열림 수정** — 프로젝트 메타데이터 조회가 느리거나 실패할 때(예: 첫 `cmake` configure가 오래 걸리는 프로젝트에서 타겟 미선택) 설정 페이지가 빈 화면으로 열리던 문제. 즉시 페인트 + 로딩 표시 + 실패 시 인페이지 에러 배너로 수정.
- **Marketplace 아이콘 수정** — 아이콘 배경이 불투명 검정이라 검은 사각형으로 보이던 문제. 투명 배경(타이트한 드롭섀도)으로 재생성.
- **런그룹 런처 표기** — 그룹 실행 중 상태바 런처가 숫자만이 아니라 `N running`으로 표시.

### 4.4 알려진 이슈

- **TC-11 — WSL/Remote 수동 검증 미수행** (v1.0.0에서 이월, 변동 없음). README *Known limitations* 참조.

- 관련 Milestone: MS-018 (Run Group 준비 감지)

### 6.2 신규 기능

- **Run Group 준비 게이트** — Run Groups 탭의 멤버별 **Ready when** 컨트롤로 준비 기준 선언:
  - **process start** (기본값, 기존 동작) — 프로세스 실행 즉시 준비.
  - **port open** — `localhost:<port>` TCP 연결 성공 시 준비.
  - **HTTP status** — `GET <url>`이 기대 상태코드(기본 `200`) 반환 시 준비.
- 게이트는 통과하거나 멤버의 **timeout**이 만료될 때까지 폴링한다. 준비되지 않은 멤버는 그룹 시작을 중단하고 이미 시작된 멤버를 teardown하며, 긴 대기는 진행 알림에서 **취소** 가능. 게이트 없는 멤버는 기존 동작 유지(기존 그룹 무영향).

### 6.3 개선 사항

- **Run Groups 탭 정리** — 멤버를 스테이지 순 카드로 표시(스테이지·준비 게이트·**Remove** 버튼), 전체 체크박스 목록 대신 **Add a project** 드롭다운으로 추가. 멤버 실행 시 기본 칩 값 자동 시드(예: Node **Script** → `start`).
- **Project 탭 강화** — 감지된 프로젝트를 카드로 표시(어댑터·매니페스트 경로·Doctor 기반 툴체인 상태·활성 프로필·칩별 옵션 개수 요약). 카드 클릭으로 프로젝트 전환.
- **문서** — README 상태바 스크린샷을 6개 언어 라인업으로 리프레시(Go·Node.js/TypeScript 추가, 히어로 이미지 갱신).

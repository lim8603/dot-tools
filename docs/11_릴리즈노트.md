## 1. 개요

DevSwitcher Tools는 여러 언어 프로젝트(Rust · C++/CMake · C# · Python · Go · Node.js/TypeScript)를 하나의 VSCode 상태바 UX로 전환·빌드·실행·디버그하는 VSCode 확장이다. 본 문서는 v0.1.0(2026-08-16)부터 v1.1.0(2026-08-19)까지의 전체 릴리즈 이력을 기록한다.

- 사실 관계는 `CHANGELOG.md`(영문 원본)를 기준으로 하며, CHANGELOG에 없는 사실은 추가하지 않는다.
- 각 릴리즈의 관련 Milestone은 `.cowork/04_implementation/milestone_registry.md`를 기준으로 한다.
- **배포 방식:** v0.1.0~v0.8.0은 `.vsix` + git 태그로만 배포되었고, v1.0.0부터 Visual Studio Marketplace(`lim8603.devswitcher-tools`)와 GitHub Release로 배포된다.
- **Breaking Change:** 전 릴리즈 공통 없음 (CHANGELOG 기준 기록된 Breaking Change 없음).

## 3. v1.1.0 — 실사용 피드백 1차 (2026-08-19)

### 3.1 핵심 요약

- **첫 실사용 피드백 릴리즈.** 실무 사용에서 보고된 7건을 반영 — CMake 중첩 프로젝트의 Visual Studio식 계층 표시, 라이브러리 타겟 지원, 런그룹 멤버 디버그 기동, 설정 페이지 안정화, 아이콘 수정.
- 관련 Milestone: MS-021 (v1.1.0 실사용 피드백)

### 3.2 신규 기능

- **CMake 중첩 하위 프로젝트** — `project()` 루트 아래에서 타겟을 선언한 `add_subdirectory` 디렉토리를 **인덴트된 하위 프로젝트**로 표시(프로젝트 스위처·설정 Project 탭·설정 드롭다운). 하위 프로젝트는 루트의 빌드 트리로 configure/build 되며, **Target** 선택은 자기 디렉토리의 타겟으로 스코프된다.
- **라이브러리 타겟** — Target 선택에 static/shared/module 라이브러리가 주석("static library" 등)과 함께 표시되어 단독 빌드가 가능하다. 라이브러리 타겟의 실행/디버그는 Visual Studio처럼 안내 토스트로 차단된다(*builds, but cannot run*).
- **All targets** — 루트 CMake 프로젝트의 Target 선택에 **All targets** 항목 추가(`--target` 없는 `cmake --build` = 트리 전체 빌드). 이 상태의 실행/디버그는 단일 실행 타겟 선택을 안내한다.
- **런그룹 멤버 디버그 기동** — 멤버 카드의 **Launch** 모드(Run / **Debug**): Debug 멤버는 그룹 기동 시 해당 툴체인의 디버거로 시작되고, 준비 게이트·그룹 teardown이 동일하게 적용된다(그룹 중지 시 디버그 세션도 종료).
- **라이브러리 표시 옵션** — `devSwitcher.projects.showLibraries`(기본 켜짐, General 탭): 끄면 라이브러리 전용 하위 프로젝트와 라이브러리 타겟을 목록에서 숨긴다.
- **Switch Target 단축키** — `Ctrl/Cmd+Alt+T`로 활성 프로젝트의 타겟 선택 열기(Node는 npm script 선택).

### 3.3 개선 / 수정

- **설정 페이지 공백 열림 수정** — 프로젝트 메타데이터 조회가 느리거나 실패할 때(예: 첫 `cmake` configure가 오래 걸리는 프로젝트에서 타겟 미선택) 설정 페이지가 빈 화면으로 열리던 문제. 즉시 페인트 + 로딩 표시 + 실패 시 인페이지 에러 배너로 수정.
- **Marketplace 아이콘 수정** — 아이콘 배경이 불투명 검정이라 검은 사각형으로 보이던 문제. 투명 배경(타이트한 드롭섀도)으로 재생성.
- **런그룹 런처 표기** — 그룹 실행 중 상태바 런처가 숫자만이 아니라 `N running`으로 표시.

### 3.4 알려진 이슈

- **TC-11 — WSL/Remote 수동 검증 미수행** (v1.0.0에서 이월, 변동 없음). README *Known limitations* 참조.

## 5. v0.8.0 — Run Group 준비 감지 (2026-08-17)

### 5.1 핵심 요약

- **Run Group 준비 감지(readiness gate)** — v1.0.0 이전 마지막 기능 릴리즈. 멤버별 "준비 완료" 기준을 프로세스 시작 → 포트 open / HTTP 상태코드로 강화.
- 관련 Milestone: MS-018 (Run Group 준비 감지)

### 5.2 신규 기능

- **Run Group 준비 게이트** — Run Groups 탭의 멤버별 **Ready when** 컨트롤로 준비 기준 선언:
  - **process start** (기본값, 기존 동작) — 프로세스 실행 즉시 준비.
  - **port open** — `localhost:<port>` TCP 연결 성공 시 준비.
  - **HTTP status** — `GET <url>`이 기대 상태코드(기본 `200`) 반환 시 준비.
- 게이트는 통과하거나 멤버의 **timeout**이 만료될 때까지 폴링한다. 준비되지 않은 멤버는 그룹 시작을 중단하고 이미 시작된 멤버를 teardown하며, 긴 대기는 진행 알림에서 **취소** 가능. 게이트 없는 멤버는 기존 동작 유지(기존 그룹 무영향).

### 5.3 개선 사항

- **Run Groups 탭 정리** — 멤버를 스테이지 순 카드로 표시(스테이지·준비 게이트·**Remove** 버튼), 전체 체크박스 목록 대신 **Add a project** 드롭다운으로 추가. 멤버 실행 시 기본 칩 값 자동 시드(예: Node **Script** → `start`).
- **Project 탭 강화** — 감지된 프로젝트를 카드로 표시(어댑터·매니페스트 경로·Doctor 기반 툴체인 상태·활성 프로필·칩별 옵션 개수 요약). 카드 클릭으로 프로젝트 전환.
- **문서** — README 상태바 스크린샷을 6개 언어 라인업으로 리프레시(Go·Node.js/TypeScript 추가, 히어로 이미지 갱신).

- **Node.js / TypeScript 지원 — 6번째 언어(6개 언어 완성).**
- 관련 Milestone: MS-016 (Node/TS 어댑터 실구현)

### 7.2 신규 기능

- **Node.js/TypeScript 어댑터** — `package.json` 프로젝트가 스위처에 합류(빌드·실행·디버그).
  - **Script** 칩 — 프로젝트의 npm `scripts` 목록(실행 대상, 기본 선호 `start`/`dev`/`serve`).
  - **Package Manager** 칩 — lockfile로 npm / pnpm / yarn 자동 감지 + 수동 override.
  - **Run** = `<pm> run <script>`, **Build** = `<pm> run build`, run 인자는 `--` 뒤로 전달.
  - **Debug** — VS Code 내장 **js-debug**로 선택 스크립트 실행(추가 확장 설치 불필요).
  - 컴파일 옵션은 사용자의 `tsconfig.json`에 위치(무편집). `NODE_ENV` / `NODE_OPTIONS` / `NODE_PATH`는 설정 페이지 옵션으로 env 주입.
  - `DevSwitcher: New Project…`가 Node 프로젝트 스캐폴드(`package.json` + `index.js`). `package.json`은 절대 편집하지 않음.

## 9. v0.4.0 — Run Group (2026-08-17)

### 9.1 핵심 요약

- **Run Group** — 여러 프로젝트를 의존 순서대로 일괄 시작(예: `auth → api → web`).
- 관련 Milestone: MS-013 (Run Group, C-6)

### 9.2 신규 기능

- **Run Group** — 설정 페이지 **Run Groups** 탭에서 그룹 정의: 멤버 체크 + 멤버별 **Stage** 지정(같은 스테이지는 병렬, 높은 스테이지는 이전 스테이지의 프로세스 실행 후 대기). 그룹 버튼, 상태바 `$(run-all)` 런처, **`DevSwitcher: Run Groups…`**(+ **Stop all**)로 실행/중지. 개별 실행 중이거나 다른 그룹에서 실행 중인 멤버는 준비 완료로 간주해 skip. 이 버전의 준비 기준 = 프로세스 실행(포트/헬스체크 준비 감지는 v0.8.0에서 구현).

### 9.3 버그 수정

## 11. v0.2.0 — 시작 마법사 (2026-08-16)

### 11.1 핵심 요약

- **시작 마법사(F20)** — 폴더 → 언어 → 이름 플로우로 새 프로젝트 스캐폴드.
- 관련 Milestone: MS-008 (시작 마법사 F20)

### 11.2 신규 기능

- **`DevSwitcher: New Project…`** — Rust(`cargo new`)와 C#(`dotnet new console`)은 네이티브 스캐폴더 사용, C++(CMake)와 Python은 네이티브 도구가 없어 최소 템플릿 생성(`CMakeLists.txt` + `main.cpp` / `pyproject.toml` + `main.py`). 새 Rust 프로젝트는 상태바에 자동 선택되고, 다른 언어는 디스크에 생성된 뒤 해당 어댑터가 구현되면 스위처에 등장.

### 11.3 버그 수정

- **Features 칩** — 확인 버튼 없는 토글 리스트로 변경(클릭 즉시 적용), 개수 표시가 체크박스와 일치(빈 선택은 `none`으로 기본 on 상태와 구분). 의도적으로 빈 선택이 리로드 후에도 유지.
- **untrusted workspace** — 빌드/실행/디버그(및 네이티브 프로젝트 생성)가 스피너 멈춤으로 행 걸리지 않고 "trust this workspace" 프롬프트를 표시. 프로세스를 스폰하지 못한 채 끝난 태스크가 run lock을 잠그지 못하도록 수정.

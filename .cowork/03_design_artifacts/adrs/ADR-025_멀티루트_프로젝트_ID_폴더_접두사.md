# ADR-025 — 멀티루트 프로젝트 id에 폴더 이름 접두사, 저장 상태는 자동 이전

## ADR ID
`ADR-025`

## 제목
프로젝트 id `<adapter>:<path>`의 path는 VS Code `asRelativePath(uri)` 기본 규칙을 따른다. **작업 공간 폴더가 둘 이상일 때만** `<폴더 이름>/` 접두사가 붙는다. 단일 폴더의 id는 그대로다. 이름 규칙이 바뀐 id(멀티루트에서 예전에 접두사 없이 저장된 id, 폴더 수가 바뀐 경우)는 스캔 직후 저장 상태(선택값 · 오버레이 · 활성 프로젝트 · Run Group 멤버)를 새 id로 옮긴다.

## 상태
`Accepted`

## 날짜
2026-11-18

---

## Context (맥락)

ADR-006은 멀티루트 지원을 목표로 했지만, 모든 어댑터가 `asRelativePath(uri, false)`(폴더 이름 생략)로 id를 만들었다(리뷰 C4 · B10). 그래서 두 폴더가 각각 루트에 `package.json`(또는 `Cargo.toml` · `CMakeLists.txt`)을 가지면 둘 다 `node:package.json`이 되었다.
- `registry.project(id)`는 첫 번째만 찾으므로 두 번째로 전환할 수 없고, 선택값이 섞였다.
- CMake · VS는 같은 rel을 중복으로 보고 두 번째 폴더의 루트를 버렸다. 하위 프로젝트가 다른 폴더의 루트 밑으로 분류되기도 했다.

ADR-006의 "id는 머신 독립"(작업 공간 상대 경로)은 유지해야 하고, 사용자 대부분인 단일 폴더 사용자의 저장 상태는 건드리지 않는 것이 좋다.

## Decision (결정)

1. id 경로는 `core/projectPath.projectRelPath(uri)` 하나로 만든다. 내용은 `asRelativePath(uri)`(기본값 = 폴더가 둘 이상일 때만 폴더 이름 포함)에 구분자를 `/`로 맞춘 것이다. 7개 어댑터가 모두 이것을 쓴다.
2. CMake · VS가 `parentId`를 경로로 되돌릴 때는 `folderRelative(rel, folder)`로 폴더 접두사를 벗긴다(부모는 항상 같은 폴더 안에 있다).
3. **저장 상태 이전**(`core/projectIdMigration`, 순수 함수): 스캔된 프로젝트에 없는 저장 id `a:p`가 있으면 `a:<폴더>/p`(단일→멀티) 또는 그 반대(멀티→단일)인 프로젝트로 옮긴다.
   - 후보가 여럿이면 첫 폴더로 옮긴다. 예전의 모호한 id가 실제로 가리키던 곳이기 때문이다.
   - 첫 후보에 이미 자기 상태가 있으면 옮기지 않는다. 덮어쓰지 않고, 다른 폴더로 돌리지도 않는다.
   - 이전은 reconcile보다 먼저 돈다. reconcile은 찾지 못한 활성 프로젝트를 지우기 때문이다.

## 결과

- 단일 폴더 작업 공간: id · 저장 상태 변화 없음.
- 멀티루트: 첫 refresh에 id가 `node:alpha/package.json`처럼 바뀌고 상태가 따라간다. 프로필 export 파일도 같은 규칙의 id를 쓴다(폴더 이름이 같은 작업 공간끼리 공유 가능).
- 통합 테스트에 멀티루트 호스트(`fixtures/multiroot`, 폴더 2개)를 추가했다. 폴더별 id, 접두사 되돌리기, 폴더 단위 `scan.exclude`(v1.3.1 · D-27, 지금까지 자동 테스트 밖)를 확인한다.
- 한계: 이름이 같은 폴더 두 개(`.code-workspace`에서 이름을 따로 주지 않은 같은 이름 폴더)는 여전히 구분되지 않는다. VS Code 자체의 `asRelativePath` 한계를 그대로 따른다.

## 대안

- **항상 폴더 이름 포함**(`asRelativePath(uri, true)`): 단일 폴더 사용자 전원의 id가 바뀌어 모두 이전이 필요하다. 기각.
- **폴더 인덱스 접두사**(`0/…`): 폴더 순서를 바꾸면 id가 흔들리고 머신 독립성(ADR-006)이 약해진다. 기각.

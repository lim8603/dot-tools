# ADR-013 — 캐노니컬 파일 무편집 = 영구 불변식 (C-3 폐기)

## ADR ID
`ADR-013`

## 제목
확장은 사용자의 캐노니컬 빌드 파일(`Cargo.toml`·`CMakeLists.txt`·`*.csproj`·`pyproject.toml` 등)을 **절대 편집하지 않는다.** ADR-011에서 v2로 이월했던 "호출 구성 오버레이 → 캐노니컬 파일 영구 반영(편집/승격)"(백로그 C-3)을 **폐기(Won't Do)** 하고, "파일 무편집"을 v2 이후로도 유지되는 영구 불변식으로 확정한다. 후속으로 `LanguageAdapter.persistSetting` 계약을 제거한다.

## 상태
`Accepted`

## 날짜
2026-08-16

---

## ADR 필요성 판단

- 제약·확장성: 설정 저장 모델(오버레이 전용 vs 파일 편집 병행)을 장기적·불가역적으로 규정한다. 인터페이스 계약(`persistSetting`)까지 정리한다.
- 보안·안전: 사용자 소유 파일의 무결성(주석·포맷·머지 상태) 보존 여부를 규정한다.
- 두 축 이상이 얽히고 되돌리기 어려운 결정 → ADR로 남긴다. ADR-011의 열린 v2 항목을 종결한다.

---

## Context (맥락)

ADR-011(호출 구성 오버레이)은 v1에서 캐노니컬 파일 국소 편집(구 §8.7)을 걷어내고 호출 시점 주입으로 대체했다. 다만 "오버레이를 파일에 영구 반영(승격)하는 기능"을 **v2로 이월**(백로그 C-3)해 열어두었다.

세션 #007에서 INT-001("다언어 통합 상태바 UX") 완주 로드맵을 정리하며 C-3의 존치 여부를 재검토했다. 판단 결과, C-3은 v2에서 착수할 후보가 아니라 **설계 정신과 충돌하는 항목**이라는 결론에 이르렀다.

- INT-001의 핵심 정체성은 "**중계(relay) 도구**" — 사용자의 프로젝트를 대신 전환·빌드·실행할 뿐, 소유하거나 고쳐 쓰지 않는다.
- 파일 편집이 노리는 "설정 영속화·팀 공유"는 이미 **프로파일 export/import(F12, TASK-015)** 가 파일 무편집으로 해결하고 있다.

---

## Decision Drivers (결정 요인)

- SSOT·중계 정신(ADR-007) 유지 — 캐노니컬 파일은 사용자의 진실이며 확장은 읽기만 한다.
- 사용자 파일 무결성 보호 — 주석/포맷 손실, 머지 충돌, 빌드 설정 손상 위험 원천 차단.
- 계약 단순성 — 실행되지 않는(전 어댑터 `notImplemented` 스텁) 파일 편집 계약을 제거해 인터페이스가 불변식을 코드로 강제.
- 중복 제거 — 영속화·공유 필요는 export/import가 이미 충족.

---

## Options Considered (검토한 옵션)

### Option A: C-3을 v2 백로그에 존치 (ADR-011 현행 유지)
- 장점: 수동 CLI 빌드/CI/비사용 팀원에게도 오버레이 값이 적용되도록 파일에 남길 수 있다.
- 단점: 파일 소유/파괴 위험, TOML/XML 파서·라인 편집 재도입, 머지 충돌, "당신 파일을 건드리지 않는다"는 보증 붕괴, export/import와 기능 중복.

### Option B: C-3 폐기 + "파일 무편집" 영구 불변식 확정 — 채택
- 장점: 중계 정신·파일 무결성 보증을 영구 원칙으로 승격. `persistSetting` 계약 제거로 인터페이스 단순화. 영속화 필요는 export/import로 충족.
- 단점: 오버레이 값은 앞으로도 DevSwitcher 호출 경로에서만 적용된다(수동 CLI/CI 미적용) — 설계된 한계로 수용.

---

## Decision (결정)

**Option B** — C-3(오버레이→캐노니컬 파일 영구 편집/승격)을 **폐기**하고, 다음을 확정한다.

- **불변식**: 확장은 어떤 버전에서도 사용자의 캐노니컬 빌드 파일을 편집하지 않는다. 계층 ②(캐노니컬 정의)는 **영구 읽기 전용**이다. 계층 ③(호출 구성 오버레이)만 확장이 소유하며, 값은 `workspaceState`에만 저장하고 호출 시 주입한다.
- **예외 아님 확인**: F20 시작 마법사에서 CMake/Python이 `workspace.fs`로 파일을 **작성**하는 것(D-13)은 "빈 폴더에 신규 생성"이지 "기존 사용자 파일 편집"이 아니므로 불변식과 무관하다.
- **계약 정리(TASK-026)**: `LanguageAdapter.persistSetting(project, key, value)` 을 인터페이스에서 제거하고 4개 어댑터의 스텁을 삭제한다. `interface_contract.md` §4와 ADR-007·ADR-011의 관련 문구를 "무편집 영구 불변식"으로 정리한다.
- **영속화·공유 경로**: 설정을 저장·공유할 필요는 **프로파일 export/import(F12)** 로 안내한다(파일 무편집).

---

## Consequences (결과)

### 긍정적
- 중계 도구 정체성과 파일 무결성 보증을 영구 원칙으로 확정 — 사용자 신뢰·셀링포인트 강화.
- 파일 파서/라인 편집을 v2에서도 도입하지 않음 → 장기 구현·리스크 감소.
- 죽은 계약(`persistSetting`) 제거로 인터페이스가 불변식을 코드로 표현.

### 부정적 / Trade-off
- 오버레이 값은 DevSwitcher 호출 경로에서만 적용된다(수동 CLI/CI/비사용 팀원 미적용). "확장 없이도 리포에 설정이 남아야 한다"는 요구는 지원 범위 밖으로 두고, 사용자가 직접 파일을 편집하도록 안내한다.
- ADR-011의 "편집은 v2 이월" 문구가 무효화된다(본 ADR이 종결).

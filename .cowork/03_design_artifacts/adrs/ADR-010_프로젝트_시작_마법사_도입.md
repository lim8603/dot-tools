# ADR-010 — 프로젝트 시작 마법사 도입 (DevSwitcher = 스위처 + 이니셜라이저)

## ADR ID
`ADR-010`

## 제목
매니페스트가 없는 폴더에서 새 프로젝트를 시작하는 "시작 마법사"를 도입해, DevSwitcher를 기존 프로젝트 스위처이자 프로젝트 이니셜라이저로 확장한다.

## 상태
`Accepted`

## 날짜
2026-08-13

---

## ADR 필요성 판단

- 제약·확장성: 확장의 정체성(스위처 → 스위처+생성기)과 `LanguageAdapter` 계약을 장기적으로 바꾼다.
- 운영·UX 영향: "빈 폴더 → 시작" 경로가 열려 파일 부재 처리의 비대칭이 해소된다.
- 두 축 이상 얽혀 있어 ADR로 남긴다.

---

## Context (맥락)

감지는 전적으로 매니페스트(`Cargo.toml`/`CMakeLists.txt`/`*.csproj`/`pyproject.toml`) 존재 기반이라, 매니페스트가 없으면 그 언어 프로젝트는 "없는 것"으로 간주되어 상태바가 침묵한다(E3). 반면 **도구** 부재(cargo/CodeLLDB/target)는 Doctor·온디맨드 설치로 **능동 복구**된다.

즉 *"도구가 없으면 설치 유도"* 는 있는데 *"매니페스트가 없으면 생성"* 은 없는 **비대칭**이 존재했다. 이는 설계된 결정이 아니라 매니페스트 기반 감지에서 떨어져 나온 **미설계 공백**이었고, 빈 폴더에서 특정 언어로 시작하려는 사용자는 진입 통로가 없었다.

## Decision Drivers (결정 요인)

- 빈 폴더 → 언어 선택 → 바로 시작하는 온보딩 경험 확보
- 파일 부재 처리의 비대칭 해소(도구는 복구되는데 매니페스트는 안 되던 문제)
- 기존 "위임" 철학과의 정합 — 확장이 파일을 직접 짜지 않고 네이티브 도구에 위임

## Options Considered (검토한 옵션)

### Option A: 기능으로 추가 (시작 마법사) — 채택
- 장점: 부재 비대칭 해소, 온보딩 매끄러움, 모든 언어 공통 진입점
- 단점: 스코프 확장, 어댑터 계약에 init 추가, 로드맵 영향

### Option B: 명시적 비목표
- 장점: 스코프 유지, "스위처" 철학 고수
- 단점: 빈 폴더 시작 경로 공백 유지

### Option C: 안내만 (외부 도구/명령 링크)
- 장점: 저비용
- 단점: 반쪽 대응 — 여전히 사용자가 직접 실행

## Decision (결정)

**Option A** — "새 프로젝트 시작 마법사"를 도입한다.

- **대상 언어**: 모든 언어(Rust/C++/C#/Python). 스위치·빌드·디버그 실구현은 v1 Rust 단독이지만, **시작 마법사는 v1에서 4개 언어 모두 실동작**한다(네이티브 init 호출은 단순해 전체 어댑터 실구현 없이 가능).
- **트리거**: 수동 호출 — 명령 `DevSwitcher: 새 프로젝트 시작`(`devSwitcher.newProject`). 빈 폴더 자동 감지·자동 제안은 하지 않는다.
- **범위**: 기본 템플릿 생성까지. 각 어댑터가 언어의 네이티브 도구에 위임 — `cargo new`, `dotnet new console`, cmake 최소 템플릿, python 기본 `pyproject.toml`.
- **경계**: 확장은 오케스트레이션만 담당하고 실제 파일 생성은 네이티브 도구가 수행(SSOT·위임 원칙 유지). 생성 후 ManifestWatcher(F17)가 새 매니페스트를 감지해 스위처에 자동 등장.

## Consequences (결과)

### 긍정적
- 파일 부재의 **능동 복구 경로** 확보 — 도구/매니페스트 비대칭 해소.
- 모든 언어 공통 진입점 — 비Rust도 "시작"만은 v1에서 동작.
- 네이티브 도구 위임으로 SSOT·위임 원칙 유지.

### 부정적 / Trade-off
- `LanguageAdapter` 계약에 프로젝트 생성 능력(예: `createProject`/템플릿 선언) 추가 필요 → M1 인터페이스 확정에 반영.
- v1 스코프·일정 증가 — 로드맵에 마법사 작업 추가 필요.
- 기존 `functional_spec`의 "부재 시 스캐폴드는 비목표" 결정을 **뒤집음**.

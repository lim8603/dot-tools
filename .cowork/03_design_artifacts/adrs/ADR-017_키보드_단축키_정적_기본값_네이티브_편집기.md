# ADR-017 — 키보드 단축키 = 정적 기본값 + 네이티브 편집기 딥링크

## ADR ID
`ADR-017`

## 제목
키보드 단축키(MS-017, v0.7.0)는 **정적 기본 키바인딩**(package.json `contributes.keybindings`)으로 제공하고, **변경은 VSCode 네이티브 Keyboard Shortcuts 편집기로 위임**한다. 설정 페이지 General 탭은 명령·기본 키를 나열하고 네이티브 편집기로 **딥링크**(`workbench.action.openGlobalKeybindings` + `@ext:lim8603.devswitcher-tools` 필터)만 건다. 인페이지에서 키를 캡처해 런타임에 재바인딩하는 방식은 **채택하지 않는다** — VSCode에 런타임 키바인딩 등록 API가 없고, 사용자 `keybindings.json`을 직접 편집하는 것은 취약·비관용적이기 때문이다. 기본 키는 **직접 바인딩 `Ctrl+Alt+<글자>`**(Mac `Cmd+Alt+<글자>`)이며 `when: devSwitcher.hasProjects` 컨텍스트 키로 스코프해 충돌을 최소화한다.

## 상태
`Accepted`

## 날짜
2026-08-17

---

## ADR 필요성 판단

- 제약: **VSCode 플랫폼 제약**(런타임 키바인딩 등록 불가)이 구현 방식을 근본적으로 규정한다. 이 사실을 모르면 "인페이지 재바인딩"이라는 불가능한 설계로 빠질 수 있다.
- 운영 영향·확장성: 기본 키 스킴·스코프·변경 경로는 6개 언어 전 명령의 UX를 좌우하고, 이후 명령이 늘어도 같은 패턴을 따른다.
- milestone 등록 시 "구현방식은 착수 시 ADR 확정"으로 명시(D-21) → ADR로 남긴다.

---

## Context (맥락)

MS-017은 v1.0.0 로드맵 3단계(v0.7.0): 6개 언어 명령 세트가 확정된 뒤 **기본 키보드 단축키를 제공하고 사용자가 변경**할 수 있게 한다(팀 필수 UX). 현재 `contributes.keybindings`는 **전무**하다.

핵심 제약을 구현 착수 시 확인했다: **VSCode 확장은 런타임에 키바인딩을 등록/변경할 수 없다.** 키바인딩의 출처는 오직 ① 확장의 `contributes.keybindings`(정적, 설치 시 확정) ② 사용자의 `keybindings.json`(사용자가 편집)뿐이다. `registerKeybinding` 같은 API는 없다.

따라서 "설정 페이지에서 키를 눌러 캡처 → 즉시 적용"은 **원리적으로 불가능**하다. 유일한 우회는 확장이 사용자 `keybindings.json`(전역 config 경로)을 직접 파일 편집하는 것인데, JSONC(주석 포함) 파싱·머지·플랫폼 경로·충돌 감지 우회로 취약하고, ADR-013("파일 무편집, 호출 시점 주입")의 정신에도 반한다.

반면 VSCode는 **네이티브 Keyboard Shortcuts 편집기**를 제공하고, `workbench.action.openGlobalKeybindings` 명령에 쿼리 문자열을 넘겨 특정 확장/명령으로 **필터한 채 열 수 있다**. 이 편집기는 충돌 감지·When 절·플랫폼별 키·사용자 오버라이드를 모두 견고하게 처리한다.

---

## Decision Drivers (결정 요인)

- **플랫폼 관용성** — 키바인딩 변경의 SSOT는 VSCode의 Keyboard Shortcuts 편집기다. 여기에 위임하면 충돌 감지·When 절·플랫폼별 처리를 공짜로 얻는다.
- **파일 무편집 정신(ADR-013)** — 사용자 config 파일을 확장이 직접 쓰지 않는다. 기본값은 정적 기여, 변경은 네이티브 편집기.
- **충돌 최소화** — `when: devSwitcher.hasProjects`로 스코프해 DevSwitcher 프로젝트가 있을 때만 단축키가 활성화되도록 한다(그 외엔 무충돌·무동작).
- **어댑터 무지(INV-2)** — 단축키는 명령(build/run/debug/switch/settings) 레벨이라 어댑터/언어와 무관하다. 6개 언어 공통.

---

## Options Considered (검토한 옵션)

- **Option A — 정적 기본값 + 네이티브 편집기 딥링크 (채택)**: `contributes.keybindings` 기본값 + General 탭에 명령·기본키 나열 + `openGlobalKeybindings` 딥링크(확장 필터). 견고·관용·저위험. 단점: "현재 사용자 오버라이드 키"를 API로 읽을 수 없어 General 탭은 *기본값*을 표시(변경은 편집기가 SSOT).
- **Option B — 인페이지 캡처 → `keybindings.json` 직접 편집**: 설정 페이지에서 키 캡처 후 사용자 config 파일을 확장이 편집. JSONC 파싱·머지·충돌 우회로 취약, 비관용적, ADR-013 반함. 비채택.
- **키 스킴**: **직접 바인딩 `Ctrl+Alt+<글자>` (채택)** — 단일 코드·빠름·발견 용이, `when` 스코프로 충돌 완화(일부 국제 키보드 AltGr 주의는 사용자 재바인딩으로 해소) vs 코드 프리픽스 `Ctrl+K <글자>`(거의 무충돌이나 두 번 입력).

---

## Decision (결정)

**Option A + 직접 바인딩 스킴.** 세부:

- **정적 기본 키바인딩**(`contributes.keybindings`), `when: devSwitcher.hasProjects`, Mac 변형 포함:
  - `devSwitcher.build` → `Ctrl+Alt+B` / `Cmd+Alt+B`
  - `devSwitcher.run` → `Ctrl+Alt+R` / `Cmd+Alt+R`
  - `devSwitcher.debug` → `Ctrl+Alt+D` / `Cmd+Alt+D`
  - `devSwitcher.switchProject` → `Ctrl+Alt+P` / `Cmd+Alt+P`
  - `devSwitcher.openSettings` → `Ctrl+Alt+,` / `Cmd+Alt+,`
- **컨텍스트 키**: orchestrator가 스캔(`refresh`) 때 `devSwitcher.hasProjects`를 `setContext`한다(프로젝트 0개면 false → 단축키 무동작).
- **General 탭 "Keyboard Shortcuts" 섹션**: 확장 자신의 `packageJSON.contributes.keybindings`를 읽어(SSOT·드리프트 없음) 명령·기본키(현 플랫폼)를 표로 나열 + "Open Keyboard Shortcuts" 버튼(`openGlobalKeybindings`, 쿼리 `@ext:lim8603.devswitcher-tools`) + 행별 편집 링크(해당 명령으로 필터). "기본값이며 변경은 네이티브 편집기에서" 안내.
- **변경 경로**: 사용자는 네이티브 편집기에서 변경한다. 확장은 `keybindings.json`을 읽거나 쓰지 않는다.
- **VSCode 내장 키 불간섭(Human, 세션 #013)**: **F5·Ctrl+Shift+B·F7 등 내장 키는 오버라이드하지 않는다.** DevSwitcher의 Debug/Build는 내장(F5=launch.json·Ctrl+Shift+B=tasks.json)과 **다른 동작**(활성 DevSwitcher 프로젝트를 어댑터로 구동)이므로 별도 키(Ctrl+Alt+*)로 둔다. 우리 Task는 TaskProvider 미등록이라 Ctrl+Shift+B 태스크 목록에도 나타나지 않는다. 대신 README·General 탭에 **"원하면 F5/Ctrl+Shift+B를 DevSwitcher로 리맵하는 법"**(네이티브 편집기에서 `devSwitcher.debug`/`devSwitcher.build`에 키 지정)을 **안내만** 제공한다 — 강제 오버라이드로 launch.json/tasks.json 사용자를 놀라게 하지 않는다.

## Consequences (결과)

### 긍정적
- 견고·관용적: 충돌 감지·When 절·플랫폼별·오버라이드를 VSCode가 처리.
- 파일 무편집 정신 유지: 사용자 config를 확장이 편집하지 않는다.
- `when` 스코프로 무프로젝트 시 무충돌. 6개 언어 공통 명령 레벨.

### 부정적 / Trade-off
- General 탭은 사용자의 *현재 오버라이드* 키가 아니라 *기본값*을 표시한다(오버라이드 키를 읽는 공개 API 부재). "변경은 편집기에서" 안내로 보완.
- `Ctrl+Alt+<글자>`는 일부 국제 키보드에서 AltGr과 겹칠 수 있다 → 사용자 재바인딩으로 해소(네이티브 편집기).
